## refresh-feed-cache verify-värav: fikseeritud lävi → isekohanduv DB-võrdlus

**Probleem (Tarmo):** `refresh-feed-cache.sh` lõpp-värav kasutas FIKSEERITUD läve `MIN_MEILI_DOCS=15000`. Pärast eilset archive'i (18062→14820) langes doc-count alla 15000 → värav kukkus **vale-alarmiga**, kuigi reindeks õnnestus. Fikseeritud lävi lõheneb iga kord kui kataloog muutub (archive kahandab, feed-import kasvatab).

**Kinnitatud — 04:00 (ja 00:00, 08:00) cron kukkus täpselt sel põhjusel:** Meili doc-count=14820 = DB elus 14820 (langevad kokku), viimane reindeks-task 2026-07-24T08:01Z õnnestus, aga `14820 < 15000` → Coolify "Failed". Cron on olnud punane igal jooksul alates eilsest arhiveerimisest.

**Fix (isekohanduv, commit `main 995366f5` / `taxonomy-v4 15613ef4`):**
- `index-meilisearch.mjs`: väljastab `EXPECTED_DOCS=<keepIds.size>` (= elusate toodete arv DB-s: published AND ¬deleted AND feed_status != archived). Ainus tõde "mitu dokki PEAB olema".
- `refresh-feed-cache.sh`: capture'ib EXPECTED_DOCS, võrdleb Meili doc-count'i selle vastu lubatud väikese hälbega (`max(50, 1%)` — async/paralleelne kirjutus). Fikseeritud arvu EI ole → ei lõhene kataloogi muutudes. Reindeks-task-värskuse kontroll (finishedAt > RUN_START) säilis.
- Kui EXPECTED_DOCS puudub (vana script image'is) → fail-loud "redeploy vajalik".

**Testitud (isoleeritud, ei jooksutanud rasket pipeline'i):** A(14820=14820)→OK · B(lahknev docs vs exp)→FAIL · C(wipe docs=0)→FAIL · D(async-hälve dev=20)→OK · E(vana reindeks-task)→FAIL. index-meilisearch väljastab EXPECTED_DOCS=14820, reindeks puhas.

**⚠️ REDEPLOY-CAVEAT:** live k33g-konteiner jookseb veel VANU baked-skripte (fikseeritud 15000, ilma EXPECTED_DOCS). Cron kukub vale-alarmiga edasi (12:00, 16:00...) kuni **taxonomy-v4 (15613ef4) Coolify redeploy**. Alternatiiv: hot-patch konteinerisse (docker cp mõlemad failid /app/scripts/) = ajutine, kaob redeploy'l — Tarmo otsus.
