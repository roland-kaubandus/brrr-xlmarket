### [1] STACK-LOCK VANEMA-HOIDMISE PÄRANDUMINE (üldine juurparandus)
- **Probleem (latent):** öine `import-pipeline.sh` hoiab bash-stack-lukku (rida 40) kogu `--execute` jooksu.
  Node-alamsamm (glossary [6.4] LIVE DB-write) kutsus `withStackLock` → nägi võõrast PID-faili (bash pid ≠ node pid)
  → ootas 60s → `ELOCKBUSY`. Pipeline [6.4] rc≠0 = WARNING → **glossary LIVE kirjutus EI ÕNNESTUNUD KUNAGI öises hookis.**
- **Fix:** nii bash kui node teek eksportvad `XL_STACK_LOCK_HELD=1` reaalse luku võtul. Alamprotsessid pärivad env
  kaudu → nende acquire = **re-entrant no-op** (ei puutu PID-faili, ei vabasta vanema lukku). Üks mehhanism KÕIGILE
  tulevastele pipeline-sammudele (HARD RULE #5). Failid: `scripts/lib/stack-lock.sh`, `scripts/lib/stack-lock.mjs`.
- **Test:** `scripts/test-stack-lock-inherit.sh` — **16/16** (simuleerib öist jooksu glossary LIVE; node+bash alam no-op;
  vanema lukk säilib; release unset; regressioon: standalone node võtab+vabastab oma luku normaalselt).
- `import-pipeline.sh` [6.8] rida: eemaldatud `XL_STACK_LOCK_HELD=1` prefiks (nüüd päritud rida-40-st).
